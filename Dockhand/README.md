# shipctl · 手游控制台（MaiBot 插件）

把手机或模拟器上的策略手游，变成能"看一眼、说一句"的东西。

插件本身**不截图、不识别、不点击**。它只做三件事：把目标翻译成步骤、逐步骤把关、把结果说给人听。真正看屏幕和动手指的，是你电脑上跑的那个 agent。

```
  MaiBot（插件进程）               你电脑（agent 进程）              手机 / 模拟器
  ─────────────────                ────────────────────              ─────────────
  "去看看主界面"      ──HTTP──▶      截屏 → 特征匹配 → 判断现在是      adb / 投屏
  闸门：能不能动                    哪个界面 → 要做哪一步
  状态机：下一步是什么   ◀──JSON──    执行（或演练时只说不做）    ──▶   点一下
```

把这个边界划清楚，是因为它解决了一个具体问题：**分辨率不一样，坐标就没用了**。

插件跑在别人的容器里，别人的电脑分辨率、模拟器缩放、DPI、系统语言、游戏 UI 缩放全都不一样。任何写死的坐标在别人机器上必然错位，而错位之后还继续点，就是在别人的账号上乱点。所以这些信息一律不进插件、不进仓库、不进配置。识别必须发生在能看到真实屏幕的那台机器上。

---

## 它做什么 / 不做什么

| 做 | 不做 |
| --- | --- |
| 接收目标（"确认在主界面"）并编排步骤 | 不内置任何游戏的识别规则 |
| 每一步之前过闸门（演练、免责、热键、校准、限流、熔断） | 不读屏幕像素，不保存截图到仓库 |
| 说不出当前界面是什么时候立即停 | 不在识别不确定时"猜一个最像的"继续执行 |
| 记录执行轨迹，失败能复盘 | 不做后台常驻轮询、不主动推送消息 |
| 演练模式下完整跑一遍并告诉你"本来会做什么" | 不承诺绕过任何反作弊，也不建议绕 |

## 三分钟装起来（只演练，不动手）

**前提**：电脑上的 agent 已经在跑，并且你从电脑浏览器能打开它的地址。

1. 把插件目录放进 MaiBot 的 `plugins/`，在 WebUI 里确认它被加载。
2. 打开配置，至少填一项：`connection.base_url`。
   - 最常见的错：填 `127.0.0.1`。MaiBot 通常在容器里，`127.0.0.1` 指的是容器自己。要填电脑的局域网地址，比如 `http://192.168.1.10:8765`。
   - 判断标准很简单：电脑浏览器能打开这个地址，手机照抄就对了。
3. 保持 `safety.dry_run = true`，什么别的都先别改。
4. 发一句：

```
/ship status
```

能列出 agent 版本、当前分辨率、识别到的界面、以及"现在处于演练模式"，就说明链路通了。

5. 再发：

```
/ship run look_main
```

演练模式下它会真的去截屏、真的去识别，然后告诉你"当前是主界面，置信度 0.96，本来会执行 assert_main（只读断言）"。**它不会点任何东西**。

到这一步，你已经验证了整条链路，而且没有承担任何操作风险。要不要继续往实跑走，见下面的"从演练到实跑"。

## 命令

`/ship` 是运维入口，管的是"这台机器现在的状态"；目标执行走 Tool（模型自己判断该调哪个）。

| 命令 | 用途 |
| --- | --- |
| `/ship` `/ship help` | 帮助与当前模式 |
| `/ship status` | 完整状态：连接、模式、校准、熔断、包、最近轨迹 |
| `/ship packs` | 列出可用适配包，标出哪个是 demo |
| `/ship observe` | 只读看一眼：现在是什么界面、置信度多少 |
| `/ship run <目标>` | 按名字执行一个目标（托管模式下模型会自己调，这里给手动排查用） |
| `/ship pause` / `/ship resume` | 远程暂停 / 恢复。暂停是本地热键之外的第二条路，不替代热键 |
| `/ship reset` | 解除熔断。**不会**自动恢复执行，只是允许下一次 |
| `/ship calibrate` | 重新校准（分辨率或 UI 缩放变了之后做一次） |
| `/ship diag` | 生成脱敏诊断包路径，出问题时要的就是这个 |
| `/ship disclaimer` | 看免责声明全文 |
| `/ship accept` | 记录"我已阅读并接受" |

Tool 只有四个，按"读/写"分层，理由写在 `plugin.py` 顶部：

| Tool | 性质 | 说明 |
| --- | --- | --- |
| `ship_state` | 只读 | 状态 + 感知结果。安全，模型可以随便调 |
| `ship_goal` | 写入 | 执行一个目标。所有闸门都在这一条路径上 |
| `ship_control` | 写入 | 暂停 / 恢复 / 解除熔断 / 校准 |
| `ship_report` | 只读 | 轨迹、诊断、帮助文本 |

## 从演练到实跑：四道门，一道都不能省

实跑不是改一个 `dry_run = false` 就完事。下面四项是硬门槛，缺一项插件就拒绝实跑（不是警告，是拒绝）。

1. **接受免责声明**：`/ship accept`。里面写清了账号风险、识别错误风险、以及"出问题你得自己承担"。
2. **配好暂停热键**：在电脑侧 agent 里设置，并把热键名填进 `safety.pause_hotkey`。
   - 插件只能校验"你填了没有"，**无法校验"它真的能按停"**。这个局限写在文档里，不藏着。填了但 agent 那边没配，出事时按下去是没反应的。
3. **完成校准**：`/ship calibrate`。让 agent 知道你屏幕的分辨率和缩放比例。
4. **关掉演练**：`safety.dry_run = false`。

每一项都有对应的自检（`tools/selftest.py` 里 3.1~3.4 就是这四道门的断言）。改代码之后跑一遍，破了哪条会直接红。

> 建议的第一次实跑目标，不是"打一场仗"，而是最无害的那种只读目标——先确认识别是对的，再让它动。

## 适配包：插件里唯一和"具体游戏"有关的东西

`game_adapter/<包名>/` 是纯数据：

```
game_adapter/demo/
├── manifest.json     包元信息（是否 demo、协议版本、许可证）
├── states.json       界面 = 特征，不含坐标
├── goals.json        目标 = 步骤序列
├── skills.json       技能 = 只读断言或等待
└── templates/*.png   模板图（demo 里是重绘线框图）
```

三条硬约束，`tools/selftest.py` 会逐条检查：

1. **不许出现坐标/几何字段**（`x` `y` `bbox` `width` `height`…）。适配包说"这是主界面"，不说"主界面在这里"。
2. **`unknown` 是终止条件**，不是兜底状态。认不出就停，绝不"当作主界面继续"。
3. **`config.toml` 里没有坐标块**。老版本有过，删掉了，示例配置里也不留痕迹。

自带的是 **demo 包**：四个界面、三个只读目标，模板图是手绘黑白线框（不是任何游戏的截图），跑不了实操，只用来验证链路。详细格式见 [`docs/适配包格式.md`](docs/适配包格式.md)。

## 关于社区共建的边界

先写清楚，免得以后扯皮：

- **官方只发 demo 级包**。demo 的定义很具体：只有断言和等待，没有任何可执行动作，模板图是自己画的结构示意。这样做的原因是"分发一份能直接跑的脚本"和"分发一份格式说明"是完全不同的两件事，后者才是这个项目想做的事。
- **欢迎的贡献**：修 bug、补文档、写自己的适配包、改进识别思路、报告在某个分辨率/语言下失效。
- **不接受的贡献**：包含完整可运行操作序列的包、带游戏原始美术素材的模板图、绕过检测/反作弊相关的内容、以及任何"教人怎么多开刷号"的东西。
- 提交适配包前请先跑 `python tools/selftest.py`，它会告诉你包有没有踩到那三条约束。

不是洁癖。这个项目一旦开始收"完整脚本"，性质就变了。

## 出了问题怎么定位

按这个顺序，别跳步：

```
/ship status      → 连接通不通、什么模式、为什么被拦
/ship observe     → 现在识别成什么，置信度多少
/ship diag        → 生成脱敏诊断包（截图会被打码，令牌会被抹掉）
```

三条都不清楚的时候，`/ship diag` 生成的目录直接发我。里面没有你的令牌、没有你的聊天记录、截图只保留结构轮廓。

常见几条：

| 现象 | 大概率原因 |
| --- | --- |
| `连接被拒绝` / 一直超时 | `base_url` 填了 `127.0.0.1`，而 MaiBot 在容器里 |
| 能连上但 `401` | agent 令牌没填，或填了旧令牌 |
| 一直 `unknown` | 分辨率/缩放变了 → `/ship calibrate`；或包不匹配这个游戏 |
| 一切正常但 `拒绝实跑` | 四道门里有一道没过，`/ship status` 会说哪一道 |
| 跑一半自己停了 | 熔断。看 `/ship status` 里的失败原因，`/ship reset` 解除 |

## 开发

```bash
python tools/selftest.py      # 50 项：结构约束 + 演练行为 + 拦截行为 + 闸门 + 免责持久化
python tools/plugin_smoke.py  # 30 项：plugin.py 的 SDK 用法与 12 个运维子命令
python tools/e2e_dryrun.py    # 31 项：起一个真 HTTP 假 agent，走完整链路
```

三个都不需要游戏、不需要真 agent、不需要外网。改完代码先跑这三个，再谈上真机。

三者的分工不是重复：

| 脚本 | 测什么 | 什么时候跑 |
| --- | --- | --- |
| `selftest.py` | 逻辑对不对（假对象替换 client） | 改引擎、改闸门 |
| `plugin_smoke.py` | 插件注册对不对、命令崩不崩 | 改 `plugin.py`、改 Tool/Command |
| `e2e_dryrun.py` | 协议对不对、链路通不通（真 HTTP） | 改 `protocol.py`、改契约 |

`e2e_dryrun.py` 里有一条断言值得单独说：它统计假 agent 侧收到的**输入事件数**，演练全程必须是 0。这条比"返回 ok"有意义得多——返回 ok 只能说明流程走完了，输入事件数为 0 才说明真的没动。

```
engine/          通用引擎：协议、闸门、状态机、配置、轨迹
game_adapter/    适配包数据（含 base.py：包的加载与校验）
plugin.py        插件入口：4 Tool + 1 Command + 配置声明
tools/           离线自检
docs/            格式说明、agent 契约、决策记录、免责声明
```

## 这是在做什么，以及不是在做什么

这个项目的前提假设很朴素：你有一个自己玩的账号，有一台能跑模拟器的电脑，有些事重复做很烦，想让 AI 帮你按几下。

它不打算做多开、不打算刷资源、不打算在别人不知情的情况下操作别人的设备、也不打算跟反作弊较劲。这些不是"技术上做不到"，是"做了这项目就变成另一个东西了"。

如果你打算把它用在自动化会导致封号的环境里，请用小号，并且先把演练模式跑够。默认值之所以这么保守（默认演练、失败一次就熔断、认不出就停），是因为**这些默认值会在你没想到的时候替你的账号兜底**。

见 [`docs/免责声明.md`](docs/免责声明.md)。
