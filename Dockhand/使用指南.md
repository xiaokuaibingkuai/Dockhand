# 使用指南

> 本文档是本文件夹的项目使用与扩展指南，内容取自 `README.md`、`CHANGELOG.md`、`config.example.toml` 及 `docs/` 下的《适配包格式》《电脑侧Agent契约》《免责声明》《项目备忘》。安装与配置的逐字段说明见同目录《使用说明.md》。

---

## 一、先理解分工，再动手

```
插件（容器内）     : 决定"要不要做、做什么"
电脑侧 agent       : 决定"看到了什么、怎么动"
手机 / 模拟器      : 被看、被点的那一头
```

插件里只有四类模块：`engine/`（通用引擎）、`game_adapter/`（纯数据适配包）、`plugin.py`（入口：4 Tool + 1 Command + 配置声明）、`tools/`（离线自检）。

理解这条分工的价值在于后续所有操作都有明确落点：

- 想让 AI 认得新游戏 → 只改 `game_adapter/<pack_id>/` 里的 JSON 与模板图，**不碰 `engine/`**；
- 想换一台电脑、换一套投屏 → 只动电脑侧 agent 与一次校准，**不碰插件配置结构**；
- 插件里永远没有坐标：`config.toml` 没有坐标块，适配包禁止出现坐标字段。

## 二、日常使用流程

### 标准四步

| 步骤 | 命令 | 判断标准 |
| --- | --- | --- |
| 1. 看状态 | `/ship status` | 连接、模式、校准、熔断、包、最近轨迹是否正常 |
| 2. 看一眼 | `/ship observe` | 识别到的界面名与置信度是否符合预期 |
| 3. 跑目标 | `/ship run <目标>`，或由模型自行调用 `ship_goal` | 返回 `final_state` 与每步结果 |
| 4. 复盘 | `/ship diag` 或查看轨迹 | 轨迹含目标、每步结果、失败分类 |

### 读状态的顺序

`/ship status` 回答"为什么被拦"，`/ship observe` 回答"现在识别成什么"，`/ship diag` 回答"给我一份能发出去的证据"。三者不重复：出问题时按 1 → 2 → 3 顺序看，不要跳步。

### 各命令的分工

- `observe` 只读，永远不会动；
- `run` 可能动手，但受全部闸门约束；
- `status` 解释"为什么被拦"；
- `diag` 产出发给别人看的东西。

`pause` / `resume` 是热键之外的第二条暂停路径，**不替代热键**。`reset` 只表示"允许下一次"，不会自动恢复执行。

## 三、Demo 包能做什么

自带 `game_adapter/demo/` 是**纯数据**，用于验证链路：

```
game_adapter/demo/
├── manifest.json     包元信息（demo: true、协议版本、许可证）
├── states.json       界面 = 特征，不含坐标
├── goals.json        目标 = 步骤序列
├── skills.json       技能 = 只读断言或等待
└── templates/*.png   模板图（重绘黑白线框）
```

具体内容：

- **4 个可识别界面**：`main_map`（主界面，阈值 0.78）、`fleet_panel`（舰队面板，阈值 0.78）、`battle_result`（战斗结算弹窗，阈值 0.75）、`loading`（加载中，阈值 0.62）；外加 `unknown`（终止条件，`templates` 必须为空数组）。
- **3 个只读目标**：`look_main`（确认是否在主界面）、`look_fleet`（确认是否在舰队面板）、`wait_ready`（加载中则等回主界面）。
- **3 个技能**：`assert_main`、`assert_fleet`、`wait_loading`，全部只含 `assert` / `wait_for`，没有 `tap` / `swipe` / `key`。

`demo: true` 是**运行时强制**的硬约束，不是标签：demo 包即使四道门全过也只允许演练，改名绕不过去，因为校验在代码里。

## 四、写自己的适配包

适配包是插件里唯一与"某个具体游戏"有关的东西，是纯数据：四类 JSON + 一组图片，没有一行可执行代码。设计目标是"换游戏不用改插件"。

### 4.1 目录与命名

```
game_adapter/
└── <pack_id>/
    ├── manifest.json
    ├── states.json
    ├── goals.json
    ├── skills.json
    └── templates/
        ├── main_map.png
        └── ...
```

`<pack_id>` 必须匹配 `^[a-z][a-z0-9_]{0,47}$`：小写字母开头，只含小写字母、数字、下划线，最长 48 字符。原因：该 id 会出现在配置、命令、日志和 URL 里。

### 4.2 四类文件的关键字段

**manifest.json**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `pack_id` | 是 | 与目录名一致，不一致会被拒绝 |
| `name` | 是 | 显示名 |
| `version` | 是 | 包自己的版本，与插件版本无关 |
| `author` | 否 | 出识别问题时用户知道找谁 |
| `demo` | 否 | `true` 表示只读示例包，任何情况下不允许实跑 |
| `entry_states` | 否 | 进入游戏后可能落到的界面，用于判断"能不能开始" |
| `protocol_min` | 否 | 依赖的 agent 协议版本，默认 2 |
| `license` | 否 | 建议明确写，涉及第三方素材时尤其重要 |
| `format_version` | 否 | 当前为 1 |

**states.json**

| 字段 | 说明 |
| --- | --- |
| `description` | 写"看到什么能确认是这个界面"，不要只写"这是主界面" |
| `templates` | 相对本包目录的图片路径，**裁最小必要区域** |
| `min_confidence` | 匹配阈值，默认 0.75 左右；动画帧、渐变、半透明遮罩适当调低 |

三条规则：`unknown` 必须存在且 `templates` 为空数组；模板图裁小不裁大；不要把动画中间帧当模板（选稳定停留超过 1 秒的画面）。

**goals.json**

| 字段 | 说明 |
| --- | --- |
| `description` | 模型会读这句决定是否选它，要写清"什么时候该用" |
| `requires_state` | 必须在哪个界面开始，`"any"` 表示不限制 |
| `steps` | 技能名序列，可带 `args` |
| `on_fail` | `abort`（默认）或 `retry_once` |
| `max_attempts` | 最小 1 |

目标层不写动作细节：目标说"去舰队面板"，技能说"点哪个元素、等多久"。

**skills.json**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `steps` | 是 | 非空，至少一步 |
| `expect_state` | 是 | 执行完应该在什么界面，**不能是 `unknown`** |
| `pre_states` | 否 | 允许的前置界面，默认 `["any"]` |
| `timeout_ms` | 否 | 默认 30000 |
| `retryable` | 否 | 默认 `true`；涉及确认、消耗、购买的必须设为 `false` |

允许的 step 形态：

| op | 参数 | 说明 |
| --- | --- | --- |
| `tap` | `target` | 按**元素名**点击，由 agent 现场定位 |
| `wait` | `ms` | 死等，能不用就不用，改用 `wait_for` |
| `wait_for` | `state`, `timeout_ms` | 等到某个界面出现 |
| `swipe` | `target_from`, `target_to`, `duration_ms` | 按元素名滑动 |
| `key` | `name`（如 `back`） | 按键 |
| `assert` | `state` | 断言界面，不改状态，只验证 |

`tap` 的 `target` 是元素名，不是坐标、不是路径、不是百分比。元素名由 agent 在自己的模板/配置里映射到真实像素位置。

### 4.3 三条硬约束（`tools/selftest.py` 逐条检查）

1. **包内不许出现坐标或几何字段**。被拒键名（大小写不敏感）：`x` `y` `px` `py` `coord` `coords` `coordinate` `coordinates` `bbox` `box` `point` `position` `pos` `offset` `left` `top` `width` `height` `x_pct` `y_pct`。宽高也禁，因为出现它通常意味着在描述"按钮在这块区域"。
2. **`unknown` 是终止条件**。识别为 `unknown` 时立即终止当次执行，不重试、不换下一个技能；技能 `expect_state` 不能是 `unknown`；目标 `requires_state` 写 `unknown` 会被忽略。
3. **配置里没有坐标块**。`config.toml` 中任何键名含 `coord`/`x`/`y`/`bbox` 之类的字段都会被拒绝加载；旧配置若含 `[coordinates]` 会直接报错而非静默忽略。

### 4.4 从 demo 复制出自己的包

第一步永远建议是 `assert`：先确认"我能认出这个界面"，再谈"我要点它"。

1. 复制 `game_adapter/demo/` 为新目录，目录名即新 `pack_id`；
2. 改 `manifest.json` 的 `pack_id`（与目录名一致）、`name`、`version`，必要时把 `demo` 改成 `false`；
3. 换上自己的模板图，或调整 `states.json` 的界面划分与 `min_confidence`；
4. 逐步加技能，先 `assert`，再加 `wait_for`，最后才考虑动作类 step（并严格评估 `retryable`）；
5. 跑 `python tools/selftest.py`，红了先修到绿；
6. 在配置里把 `adapter.pack_id` 指向新包（留空则自动选第一个非 demo 包）。

### 4.5 常见错误对照

| 报错 | 原因 | 怎么改 |
| --- | --- | --- |
| `适配包被拒绝：... 出现坐标字段 x` | 写了坐标 | 改成 `{"target": "confirm_button"}`，由 agent 定位 |
| `技能 xxx 没有声明 expect_state` | 缺字段 | 补上执行完应该在的界面 |
| `技能 xxx 的 expect_state 不能是 unknown` | 把"不知道"当期望 | 换成具体界面 |
| `技能名 Xxx 不合法` | 有大写/空格 | 改成小写 + 下划线 |
| `pack_id 与目录名不一致` | 复制目录后忘了改 | 两处统一 |
| `目标 xxx 没有 steps` | 空目标 | 至少引用一个技能 |
| `适配包 ... 顶层必须是对象` | JSON 是数组 | 单个包是对象，不是数组 |
| 加载成功但一直 `unknown` | 模板图太大/太依赖美术/分辨率变了 | 裁小模板、降低 `min_confidence`、跑一次校准 |

## 五、对接电脑侧 agent

插件只负责"要不要做、做什么"，agent 负责"看到了什么、怎么动"。这一节给不想用现成 agent、要自己写一个的人。

### 5.1 连接与鉴权

```
http://<电脑局域网 IP>:8765
```

- 所有请求带 `X-Token: <token>`；agent 侧同时应接受 `Authorization: Bearer <token>`（两种都认，可省掉一整类"401 但 token 明明一样"的问题）；
- 令牌比对用常量时间比较（`hmac.compare_digest`）；
- 只监听局域网，**不要映射到公网**；
- 令牌为空时 agent 应拒绝所有请求并提示"未设置令牌"。

### 5.2 八个接口

| 方法 | 路径 | 用途 | 幂等 |
| --- | --- | --- | --- |
| GET | `/v2/health` | 存活检查 | 是 |
| GET | `/v2/capabilities` | 能力与版本协商 | 是 |
| GET | `/v2/observe` | 只读看当前界面 | 是 |
| POST | `/v2/skill` | 执行一个技能 | 否 |
| POST | `/v2/pause` | 暂停 | 是 |
| POST | `/v2/resume` | 恢复 | 是 |
| POST | `/v2/calibrate` | 校准 | 否 |
| POST | `/v2/screenshot` | 截图存档 | 否 |

关键约定：

- `capabilities.protocol` 必须返回，插件做**大版本协商**，不一致直接拒用。协商发生在第一次真正调用时，不在插件加载时，因为用户很可能先启动麦麦再启动 agent。**加载永远成功，是刻意的。**
- `capabilities.paused` 必须是实时值；`calibration.ok` 为 false 时 `reason` 要写人话。
- `observe` 的 `state` 必须返回，认不出就返回 `"unknown"`，`confidence` 给真实值（可为 0）。`elements` 里的 `x/y` 是运行时结果，每次现算，不进适配包、不进配置、不落盘。
- `/v2/skill` 的 `dry_run: true` 时必须只做识别与计划，把原本要做的动作放进 `would_do`。
- `/v2/skill` **不重试**（该接口不幂等，重试逻辑放在插件侧，因为插件知道哪些技能 `retryable: false`）。

### 5.3 失败分类

`ok: false` 必须带 `error_class`：

| error_class | 含义 | 插件反应 |
| --- | --- | --- |
| `E_UI` | 界面不符或认不出 | 记一次失败，可能熔断 |
| `E_TIMEOUT` | 超时 | 同上 |
| `E_DEVICE` | 设备断开 | 直接终止，不重试 |
| `E_PAUSED` | 已暂停 | 直接终止，不计失败 |
| `E_CALIB` | 未校准 | 直接终止，提示去校准 |

### 5.4 演练语义的三层保证

| 层 | 做法 | 防的是什么 |
| --- | --- | --- |
| 插件配置 | `safety.dry_run = true` 时，`run_goal` 强制把所有调用改成 dry_run | 用户忘了自己开了实跑 |
| 闸门 | `gate.check_can_act()` 在演练时不消耗限流配额，但仍执行暂停/熔断检查 | 演练状态下也被暂停/熔断拦住 |
| agent | 收到 `dry_run: true` 后只在内存里计划，返回 `would_do` | 插件算错了也不会真的点下去 |

第三层最关键：agent 里 `dry_run` 的判断必须放在**产生输入事件的那一行之前**，而不是函数入口设个变量然后忘了判。

### 5.5 校准规范

三步必须做：分辨率与缩放探测（与上次不一致就把 `calibration.ok` 置 false 并说明"从 A 变成 B"）；锚点确认（至少 3 个，建议 4 个，同一元素连续匹配 3 次偏差超过建议阈值 2% 判失败）；匹配自检（用校准结果反识别 `entry_states`，认不出任何一个就不算校准成功）。

必须重新校准的时机：分辨率或缩放变化、换模拟器/投屏软件、游戏更新改了 UI、`/ship status` 显示未校准。

插件侧 `safety.require_calibration = true`（默认）时，未校准直接拒绝实跑，**但允许演练**。

### 5.6 诊断包与脱敏

`/ship diag` 生成 zip，内容清单：

| 文件 | 内容 | 脱敏 |
| --- | --- | --- |
| `summary.txt` | 时间、插件版本、agent 版本、协议版本、模式 | — |
| `config.json` | 当前配置快照 | 令牌替换为 `<redacted>`；`base_url` 只保留主机名首段 |
| `gate.json` | 闸门快照（限流窗口、熔断状态、暂停原因） | — |
| `agent.json` | `/v2/capabilities` 全量返回 | 设备序列号打码 |
| `trace.jsonl` | 最近 N 条执行轨迹 | 不含聊天内容 |
| `screenshots/` | 现场截图（仅当用户显式要求时包含） | 默认不含 |

必须抹掉：令牌、Cookie、任何 `Authorization` 头；设备序列号、IMEI、账号名、区服 ID；聊天内容、用户昵称、消息 ID；截图里的聊天窗口、好友列表、广告位。可以保留：分辨率、缩放比例、界面状态名、置信度、错误分类与文本、技能名与步骤序列（不含坐标）。

### 5.7 最小实现顺序

1. 先只有 `/v2/health` + `/v2/capabilities`，把协议协商跑通；
2. 加 `/v2/observe`，先固定返回 `"unknown"`，跑一次 `/ship observe` 确认链路通；
3. 加模板匹配（OpenCV `matchTemplate` 就够，多尺度应对缩放），先把 demo 包四个界面认出来；
4. 加 `/v2/skill` 的 dry_run 分支，只返回 `would_do`，不落地；
5. 最后才加真实 tap/swipe，并且在此之前把热键做完。

顺序的意义：先让"什么都不做"这条路完全通，再让"能做点什么"接上去。反过来做，第一次测试就会真的点屏幕。

技术栈建议：截图 `adb exec-out screencap -p` 或模拟器接口；匹配 OpenCV `matchTemplate`（多尺度 + 灰度 + 边缘特征）；输入 `adb shell input tap` 或 `minitouch`；服务 FastAPI / Flask 均可，关键是**同步执行**——`/v2/skill` 是阻塞的，返回时技能已经跑完。

### 5.8 契约演进

`protocol` 大版本不变时只能**加**字段，不能改已有字段语义；改语义必须升 `protocol`。插件在 `capabilities()` 里做严格相等判断，升版本要两边一起升。

## 六、开发与自检

```bash
python tools/selftest.py      # 50 项：结构约束 + 演练行为 + 拦截行为 + 闸门 + 免责持久化
python tools/plugin_smoke.py  # 30 项：plugin.py 的 SDK 用法与 12 个运维子命令
python tools/e2e_dryrun.py    # 31 项：起一个真 HTTP 假 agent，走完整链路
```

三个都不需要游戏、不需要真 agent、不需要外网。改完代码先跑这三个，再谈上真机。

| 脚本 | 测什么 | 什么时候跑 |
| --- | --- | --- |
| `selftest.py` | 逻辑对不对（假对象替换 client） | 改引擎、改闸门 |
| `plugin_smoke.py` | 插件注册对不对、命令崩不崩 | 改 `plugin.py`、改 Tool/Command |
| `e2e_dryrun.py` | 协议对不对、链路通不通（真 HTTP） | 改 `protocol.py`、改契约 |

`e2e_dryrun.py` 有一条关键断言：统计假 agent 侧收到的**输入事件数**，演练全程必须是 0。返回 ok 只说明流程走完了，输入事件数为 0 才说明真的没动。

`tools/pack_release.py` 用于发布前扫描：命中保留域名、未完成标记、待补标记的一律拒绝出包。

### 发布前检查清单

- `license` 字段与 `LICENSE` 文件一致（都是 MIT）；
- 版本号与 `CHANGELOG.md` 一致；

## 八、贡献边界

**接受**：自己的 demo 级适配包（跑过 `python tools/selftest.py`）、识别思路改进（说明在什么分辨率/缩放/语言下原方案失效）、文档修正与翻译、引擎 bug 与边界情况（附脱敏后的 trace 或复现步骤）。

**不接受**：含完整可运行操作序列的包（`tap`/`swipe`/`key` 齐全）、含游戏原始美术素材的模板图、绕过检测/反作弊/设备指纹伪装相关内容、多开与批量刷资源及账号交易相关、只发 zip 没有说明的、把完整脚本改名叫 demo 的。

"教学性质"有三个可检查的判据：是否以说明为目的（有注释说明每步在演示什么）；是否可被替换成别的游戏（结构能照着改成自己的包）；去掉模板图之后是否仍成立（骨架独立于具体美术资源）。

原因写在 `docs/项目备忘.md` 第一节：分发包 B（完整游戏包）会把项目从"工具框架"变成"某个游戏的外挂"，风险承担者、素材版权、维护成本、"拿去做什么"的门槛都会随之改变。

## 九、几条被反复强调的原则

1. **默认保守**：默认演练、失败一次就熔断、认不出就停。这些默认值会在你没想到的时候替你的账号兜底。
2. **不假装更安全**：热键"未验证"就显示"未验证"；插件能检查"填没填"，检查不了"按不按得停"。让人误以为有急停、实际按下去没反应，是最坏的情况。
3. **失败即停**：`unknown` 是终止条件，最坏情况应该是"什么都没做"，而不是"在错误的界面上做了点什么"。
4. **坐标只存在于现场**：坐标只出现在 agent 的运行时结果里，不进包、不进配置、不落盘。
5. **判断权交回用户**：包写什么、什么时候实跑、诊断包发给谁，都由使用者决定；项目只负责把边界讲清楚。
