# 使用说明

> 本文档依据本文件夹内的 `README.md`、`CHANGELOG.md`、`config.example.toml` 与 `docs/` 下四篇文档撰写，所有命令、配置项、接口均取自上述文件的真实内容。

---

## 一、这是什么

**shipctl**（仓库名 **Dockhand**）是一个 MaiBot 插件：把手机或模拟器上的策略手游，变成"看一眼、说一句"的可控操作。

插件本身**不截图、不识别、不点击**。它只做三件事：

1. 把目标翻译成步骤；
2. 每一步之前过闸门（演练、免责、热键、校准、限流、熔断）；
3. 把结果说给人听。

真正看屏幕、动手指的，是运行在你自己电脑上的**电脑侧 agent**。

```
MaiBot（插件进程）               你电脑（agent 进程）              手机 / 模拟器
─────────────────                ────────────────────              ─────────────
"去看看主界面"      ──HTTP──▶      截屏 → 特征匹配 → 判断现在是      adb / 投屏
闸门：能不能动                    哪个界面 → 要做哪一步
状态机：下一步是什么   ◀──JSON──    执行（或演练时只说不做）    ──▶   点一下
```

这样划分边界的原因只有一个：**分辨率不一样，坐标就没用了**。插件跑在别人的容器里，分辨率、模拟器缩放、DPI、系统语言、游戏 UI 缩放全都不一样，任何写死的坐标在别人机器上必然错位。所以这些信息一律不进插件、不进仓库、不进配置。

### 能做与不做

| 做 | 不做 |
| --- | --- |
| 接收目标（如"确认在主界面"）并编排步骤 | 不内置任何游戏的识别规则 |
| 每一步之前过闸门 | 不读屏幕像素，不保存截图到仓库 |
| 说不出当前界面时立即停 | 不在识别不确定时"猜一个最像的"继续执行 |
| 记录执行轨迹，失败可复盘 | 不做后台常驻轮询、不主动推送消息 |
| 演练模式下完整跑一遍并说明"本来会做什么" | 不承诺绕过任何反作弊，也不建议绕 |

## 三、安装（三分钟，只演练不动手）

**前提**：电脑上的 agent 已经在跑，并且你从电脑浏览器能打开它的地址。

1. 把插件目录放进 MaiBot 的 `plugins/`，在 WebUI 里确认它被加载。
2. 打开配置，至少填一项：`connection.base_url`。
   - 最常见的错：填 `127.0.0.1`。MaiBot 通常在容器里，`127.0.0.1` 指向容器自己。
   - 要填电脑在局域网里的地址，例如 `http://192.168.1.10:8765`。
   - 判断标准：电脑浏览器能打开这个地址，手机照抄就对了（把 `127.0.0.1` 换成电脑局域网 IP）。
3. 保持 `safety.dry_run = true`，其他项先不动。
4. 在聊天里发 `/ship status`。能列出 agent 版本、当前分辨率、识别到的界面、以及"现在处于演练模式"，说明链路已通。
5. 再发 `/ship run look_main`。演练模式下它会真的截屏、真的识别，然后告诉你"当前是主界面，置信度 0.96，本来会执行 assert_main（只读断言）"，**不会点任何东西**。

到这一步，整条链路已经验证过，且没有承担任何操作风险。

### 配置文件的两种用法

`config.example.toml` 顶部已经写明：

1. 插件在 WebUI 里声明了配置表单 → 直接在 WebUI 填，不需要这个文件；
2. WebUI 里没有表单项 → 把该文件复制成 `config.toml` 放在插件目录下再改。

需要备份配置时备份 `config.example.toml`，不要备份会被 Runner 覆盖的 `config.toml`。

## 四、配置项说明

下表字段名与 `config.example.toml` 完全一致，可直接对照填写。

### [plugin]

| 字段 | 示例值 | 说明 |
| --- | --- | --- |
| `config_version` | `"0.2.0"` | SDK 2.7+ 强制要求。Runner 据此判断配置是否需要补齐或迁移，缺失会拒绝激活插件。**由插件维护，不要手改** |
| `enabled` | `true` | 插件总开关。关闭后不再接收 `/ship` 指令 |

### [connection]

| 字段 | 示例值 | 说明 |
| --- | --- | --- |
| `base_url` | `"http://192.168.1.10:8765"` | agent 地址。**不要填 `127.0.0.1`**（容器指向自己，永远连不上） |
| `token` | `""` | agent 侧生成的访问令牌。留空仅在 agent 明确允许无令牌访问时可用；默认 agent 会拒绝无令牌请求 |
| `timeout_sec` | `20` | 单次请求超时（秒）。识别一张图通常 1~3 秒，20 秒足够；太小会在电脑卡顿时频繁超时 |

### [safety]

| 字段 | 示例值 | 说明 |
| --- | --- | --- |
| `dry_run` | `true` | 演练模式：只截图、只识别、只报告"如果真跑会做什么"，不产生任何点击。**首次安装必须保持 `true`** |
| `pause_hotkey` | `""` | 紧急暂停热键名（如 `"F12"`）。必须在电脑侧 agent 里设置并生效；插件只能校验"你填了没有"，无法校验"它真的能按停" |
| `disclaimer_accepted` | `false` | 是否已阅读并接受免责声明。保持 `false` 时拒绝实跑（演练不受影响），属硬门槛 |
| `max_actions_per_min` | `20` | 每分钟最多动作次数，超过就等下一分钟。防的是异常循环高频点击，正常手动操作远达不到 |
| `breaker_threshold` | `1` | 连续失败几次触发熔断。公开版默认 1（失败一次就停）；自用可放宽到 3 |
| `breaker_cooldown_sec` | `300` | 熔断冷却时间（秒）。冷却结束也不会自动恢复，仍需手动解除 |
| `session_max_sec` | `1800` | 单次会话最长时长（秒），到点自动结束，防止"开了就忘了" |
| `require_calibration` | `true` | 实跑前是否必须完成校准，保持 `true` |

### [adapter]

| 字段 | 示例值 | 说明 |
| --- | --- | --- |
| `pack_id` | `""` | 要用的适配包 id，对应 `game_adapter/` 下的目录名。留空 = 自动选第一个"正式包"（非 demo）。**改错名字会直接报错，不会静默回落** |
| `adapter_dir` | `""` | 适配包目录的绝对路径。留空 = 用插件自带的 `game_adapter/`。只有二次开发（如把包放 NAS 上多实例共用）才需要改 |

### [notify]

| 字段 | 示例值 | 说明 |
| --- | --- | --- |
| `on_finish` | `true` | 执行结束后回一条结果。循环执行的场景建议关掉 |
| `on_error` | `true` | 出错时回一条说明。建议保持 `true`：失败却不吭声，用户会以为它还在跑 |
| `mention_on_error` | `false` | 出错时是否 @ 你。群聊建议开，私聊无所谓 |

### [runtime]

| 字段 | 示例值 | 说明 |
| --- | --- | --- |
| `loops_enabled` | `false` | 是否允许循环执行（无人值守）。默认关闭；开启前请确认熔断阈值是 1 |
| `loop_interval_sec` | `600` | 循环间隔（秒），仅在 `loops_enabled = true` 时生效 |
| `trace_keep_days` | `7` | 执行轨迹保留天数，过期自动清理 |
| `log_level` | `"INFO"` | `DEBUG` / `INFO` / `WARNING` / `ERROR`。排查问题时临时改 `DEBUG`，解决后改回 |

> 注意：本配置里**没有任何坐标、分辨率、按钮位置**。若在别处看到 `[coordinates]` 之类的配置块，那是旧版本，现在会直接被拒绝加载（`engine/config.py` 会校验未知键）。

## 五、命令（`/ship`）

`/ship` 是运维入口，管的是"这台机器现在的状态"；目标执行走 Tool（模型自己判断该调哪个）。

| 命令 | 用途 |
| --- | --- |
| `/ship`、`/ship help` | 帮助与当前模式 |
| `/ship status` | 完整状态：连接、模式、校准、熔断、包、最近轨迹 |
| `/ship packs` | 列出可用适配包，标出哪个是 demo |
| `/ship observe` | 只读看一眼：现在是什么界面、置信度多少 |
| `/ship run <目标>` | 按名字执行一个目标（托管模式下模型会自己调，这里给手动排查用） |
| `/ship pause` / `/ship resume` | 远程暂停 / 恢复。暂停是本地热键之外的第二条路，**不替代热键** |
| `/ship reset` | 解除熔断。**不会**自动恢复执行，只是允许下一次 |
| `/ship calibrate` | 重新校准（分辨率或 UI 缩放变了之后做一次） |
| `/ship diag` | 生成脱敏诊断包路径 |
| `/ship disclaimer` | 看免责声明全文 |
| `/ship accept` | 记录"我已阅读并接受" |

### Tool（4 个）

按"读/写"分层：

| Tool | 性质 | 说明 |
| --- | --- | --- |
| `ship_state` | 只读 | 状态 + 感知结果，安全，模型可随意调用 |
| `ship_goal` | 写入 | 执行一个目标。所有闸门都在这一条路径上 |
| `ship_control` | 写入 | 暂停 / 恢复 / 解除熔断 / 校准 |
| `ship_report` | 只读 | 轨迹、诊断、帮助文本 |

## 六、从演练到实跑：四道门，一道都不能省

实跑不是改一个 `dry_run = false` 就完事。以下四项是硬门槛，缺一项插件就**拒绝**实跑（不是警告，是拒绝）：

1. **接受免责声明**：`/ship accept`。也可把 `safety.disclaimer_accepted` 改为 `true`，或在 WebUI 勾选同名开关。
2. **配好暂停热键**：在电脑侧 agent 里设置，并把热键名填进 `safety.pause_hotkey`。插件只能校验"你填了没有"，无法校验"它真的能按停"——填了但 agent 那边没配，出事时按下去没有反应。
3. **完成校准**：`/ship calibrate`。让 agent 知道你屏幕的分辨率和缩放比例。
4. **关掉演练**：`safety.dry_run = false`。

每项都有对应自检：`tools/selftest.py` 里 3.1~3.4 就是这四道门的断言。

> 建议的第一次实跑目标，不是"打一场仗"，而是最无害的那种只读目标——先确认识别是对的，再让它动。

## 七、免责与反悔

### 三条确认途径

| 途径 | 操作 | 适用 |
| --- | --- | --- |
| 配置文件 | 把 `safety.disclaimer_accepted` 改成 `true` | 手改 `config.toml` 的人 |
| WebUI | 在插件配置页勾选同名开关 | 用面板的人 |
| 聊天命令 | 发 `/ship accept` | 手机上操作的人 |

`/ship accept` 会在插件数据目录写一个 `disclaimer_accepted.json`，记录确认时间与声明版本，重启后仍有效。配置与本地标记是"或"的关系，任一为真即视为已确认；`/ship status` 的 `source` 字段会显示来源（`config` / `local` / `none`）。

### 确认前后行为差异

| 项目 | 未确认 | 已确认 |
| --- | --- | --- |
| 只读看界面（`ship_state`） | 可以 | 可以 |
| 演练执行（`dry_run = true`） | 可以 | 可以 |
| 实跑（`dry_run = false`） | **拒绝**，并贴出全文 | 允许（仍需过校准与热键检查） |
| 出诊断包 | 可以 | 可以 |

### 反悔

把 `disclaimer_accepted` 改回 `false`，或删掉数据目录里的 `disclaimer_accepted.json`，插件立刻回到"只能演练"。**当前正在执行的目标不会因此中断**，要中断请用暂停（热键或 `/ship pause`）。

## 八、出了问题的排查顺序

按这个顺序，别跳步：

```
/ship status      → 连接通不通、什么模式、为什么被拦
/ship observe     → 现在识别成什么，置信度多少
/ship diag        → 生成脱敏诊断包（截图会被打码，令牌会被抹掉）
```

常见现象对照：

| 现象 | 大概率原因 |
| --- | --- |
| `连接被拒绝` / 一直超时 | `base_url` 填了 `127.0.0.1`，而 MaiBot 在容器里 |
| 能连上但 `401` | agent 令牌没填，或填了旧令牌 |
| 一直 `unknown` | 分辨率/缩放变了 → `/ship calibrate`；或包不匹配这个游戏 |
| 一切正常但 `拒绝实跑` | 四道门里有一道没过，`/ship status` 会说哪一道 |
| 跑一半自己停了 | 熔断。看 `/ship status` 里的失败原因，`/ship reset` 解除 |

诊断包内容与脱敏规则见 `docs/电脑侧Agent契约.md` 第五节：`config.json` 中令牌替换为 `<redacted>`、`base_url` 只保留主机名首段，`agent.json` 中设备序列号打码，`screenshots/` 默认不包含。

## 九、必须知道的边界

1. **暂停热键无法被插件验证**。`/ship status` 显示 `暂停热键：F12（未验证）` 是实话。装完后请实际跑一个无害只读目标、按一次热键，确认 `paused` 变成 true、后续执行被拒绝、`/ship resume` 能恢复，这个保护才算存在。
2. **演练模式不发送输入事件，但会截图**。`/ship observe` 和演练执行都会向电脑侧请求截图，截图留在电脑侧 agent 手里。
3. **"拒绝实跑"不等于"没有风险"**。四道门拦住的是插件自己发起执行，拦不住你在电脑侧手动操作，也拦不住别的程序操作那台设备。
4. **适配包是数据，能做的不只是断言**。非 demo 包若带 `tap` 步骤，加载就会执行。**只加载你自己写或你审过的包**。
5. **不涉及检测规避**。不伪造设备指纹、不隐藏 adb 连接、不改游戏内存。
6. **接口只监听局域网，不要映射到公网**。该接口能截图、能模拟点击，暴露在公网上等于把设备交出去。

风险的具体条目（账号处罚、误操作损失、违反服务条款、多开与代练风险）见 `docs/免责声明.md` 第四节，在聊天里发 `/ship disclaimer` 可看全文。
