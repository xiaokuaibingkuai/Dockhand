# 制作说明

> 本文档说明本项目**是怎么做出来的**：靠哪些东西、分成哪几层、数据怎么流动、按什么顺序写、调试时踩过哪些坑。
> 定位是"给要改它或复刻它的人看的说明书"，不是使用手册。安装配置见《使用说明.md》，日常用法与扩展见《使用指南.md》。

---

## 一、先看清楚要解决的问题

### 1.1 问题的真实形状

需求原话是"让 AI 帮我操作手游"。直接的做法是写一个插件，把屏幕坐标写死在代码里，到点就点。这条路必然失败，原因不是技术难度，而是**变量不受控**：

| 变量 | 在谁的机器上不同 |
| --- | --- |
| 分辨率 | 每台机器不同（1280×720 / 1920×1080 / 1024×640…） |
| 投屏/模拟器缩放 | 每种工具、每个用户的缩放设置不同 |
| DPI 缩放 | Windows 125%、150% 各不相同 |
| 系统语言 | 影响 OCR 与界面文案 |
| 游戏 UI 缩放 | 游戏内设置不同 |

插件的运行环境是 MaiBot 的 Runner（容器），它**看不到屏幕、没有 adb**。所以插件里任何写死的坐标，在别人机器上必然错位；错位之后继续点，就是在别人账号上乱点。

### 1.2 由此确定的三条铁律

1. **识别必须发生在能看到真实屏幕的那台机器上。** 插件永远不读像素、不存截图、不含坐标。
2. **不确定就停。** 认不出当前界面时返回 `unknown` 并终止，"最像的那个"这种善意猜测是整套系统里最危险的东西。
3. **动作要能被拦。** 演练不落地、热键能停、未校准不能动、失败会熔断。

这三条不是事后补的规范，而是决定架构的前提。整个项目就是围绕它们长出来的。

## 二、靠的是哪些东西

### 2.1 运行环境与依赖

| 层 | 依赖 | 说明 |
| --- | --- | --- |
| 宿主 | MaiBot（实测 Host 1.3.1 / SDK 2.8.2；`_manifest.json` 声明 1.4.x / 2.22.x） | 插件被 Runner 加载，容器内不可见屏幕 |
| 语言 | Python（宿主容器实测 3.13） | 插件本体只用标准库；`tools/` 里 `pack_release.py` 用到 `tomllib` |
| 第三方库 | `pydantic`（`Field`）、`maibot_sdk`（`MaiBotPlugin` / `Tool` / `Command` / `PluginConfigBase`） | **全部由宿主提供**，不随本包分发 |
| 通信 | HTTP + JSON，`http://<电脑局域网IP>:8765` | 插件是客户端，电脑侧 agent 是服务端 |
| 被控端 | adb / 投屏（由 agent 自行选择） | 插件完全不关心，属于 agent 内部实现 |

除上表外，**没有任何第三方依赖**。没有 OpenCV、没有 OCR 库、没有 numpy、没有图像库。这是刻意的：插件装在别人的容器里，多一个依赖就多一个装不上的可能。

### 2.2 实际用到的标准库，以及各自解决什么

| 标准库 | 用在哪 | 干什么 |
| --- | --- | --- |
| `urllib.request` / `urllib.error` / `urllib.parse` | `engine/protocol.py` | 唯一的 HTTP 客户端实现，不引入 `requests` |
| `hmac.compare_digest` | agent 侧契约要求 | 令牌常量时间比对，避免逐字节试探 |
| `dataclasses` | `config.py` / `trace.py` / `game_adapter/base.py` | 配置对象、步骤记录、适配包描述，全部无框架 |
| `collections.deque` | `engine/gate.py` | 一分钟滑动窗口的动作计数 |
| `hashlib` | `engine/trace.py` | 轨迹与诊断包的内容校验值 |
| `json` | 全系统 | 协议载荷、适配包、轨迹文件 |
| `zipfile` + `ZIP_DEFLATED` | `trace.py`（诊断包）、`pack_release.py`（发布包） | 打包与压缩 |
| `pathlib` | 全系统 | 路径处理，避免字符串拼接 |
| `time` | `gate.py` / `planner.py` | 限流窗口、熔断冷却、超时判定 |
| `tomllib` | `selftest.py`、`pack_release.py` | 校验 `config.example.toml` 的字段与示例一致 |
| `http.server`（`ThreadingHTTPServer`） | `tools/e2e_dryrun.py` | 起一个**真的** HTTP 假 agent，跑完整链路 |
| `types` / `importlib` 风格 stub | `tools/plugin_smoke.py` | 注入假的 `maibot_sdk` 模块，在没有宿主的环境里 import `plugin.py` |

注意最后两行：自检不是"读代码看一眼对不对"，而是**真的起服务、真的发请求**。这是这套东西能上线的前提。

### 2.3 刻意没有用的东西

- 不用截图做日志：`screenshots/` 在 `.gitignore` 里，永远不会进仓库。
- 不用坐标做配置：`config.toml` 里没有坐标块，代码里也没有。
- 不做网络层自动重试：`POST /v2/skill` 不幂等，重试必须由知道语义的一方决定。
- 不承诺绕过反作弊，也不提供相关建议（见 `LICENSE` 免责与 `docs/免责声明.md`）。

## 三、四个目录，各管一段

```
Dockhand/
├─ plugin.py          入口：把宿主的能力接到引擎上（4 个 Tool + 1 个 Command + 配置模型）
├─ engine/            通用引擎：跟具体游戏无关，换游戏不用改
├─ game_adapter/      纯数据适配包：换游戏只改这里，代码一行不动
├─ tools/             离线自检与打包：不参与运行时
└─ docs/              契约与规范：写 agent、写适配包的人看的
```

依赖方向是单向的：

```
plugin.py  ──▶  engine/  ──▶  game_adapter/base.py
    │              │
    └──────────────┴──▶  标准库
```

`engine/` 不 import `plugin.py`，`game_adapter/` 不 import `engine/`（只有 `base.py` 定义数据结构，`engine` 反过来读它）。这条约束很实用：它保证"加一个新游戏"永远不会碰引擎代码。

| 模块 | 文件 | 职责 | 换游戏要改吗 |
| --- | --- | --- | --- |
| 配置 | `engine/config.py` | 六节配置的数据类、默认值、`effective_dry_run()` | 否 |
| 错误 | `engine/errors.py` | 8 类异常 + `error_from_code()` + `wrap()` | 否 |
| 协议 | `engine/protocol.py` | `AgentClient` 9 个方法，对应 agent 的 8 个接口 | 否 |
| 闸门 | `engine/gate.py` | `SafetyGate`：7 道拦截、限流窗口、熔断、会话超时 | 否 |
| 编排 | `engine/planner.py` | `Planner`：目标 → 步骤 → 技能，逐步骤过闸门 | 否 |
| 轨迹 | `engine/trace.py` | `RunRecorder` / `TraceStore`：落盘、脱敏、限额、诊断包 | 否 |
| 运行时 | `engine/runtime.py` | `Runtime`：把上面六件组装成对外能力（状态、目标、暂停、校准、诊断） | 否 |
| 包加载 | `game_adapter/base.py` | 解析 `manifest/states/skills/goals`，校验禁坐标、禁越界键 | 否 |
| 适配包 | `game_adapter/demo/` | 状态、技能、目标的 JSON + 模板图 | **是** |
| 入口 | `plugin.py` | 配置模型、4 个 Tool、`/ship` 命令、文本格式化 | 否（只有文案） |
| 工具 | `tools/*.py` | 4 个脚本：selftest / e2e_dryrun / plugin_smoke / pack_release | 否 |

## 四、一句话怎么变成一次点击（完整时序）

以 `/ship run look_main` 为例，真实执行路径：

```
① 用户在麦麦里发：/ship run look_main
        │
② plugin.py  cmd_ship()  解析子命令 → 调 runtime.run_goal("look_main", dry_run=None)
        │
③ engine/runtime.py  run_goal()
        ├─ disclaimer_accepted()      免责未确认 → 直接拒绝（SafetyError）
        ├─ _installation_blockers()   缺连接地址 / 缺热键 / 未校准 → 列出人话原因
        └─ effective_dry_run()        "请求演练=否" 但配置为演练 → 仍按演练执行（只能加强不能削弱）
        │
④ engine/planner.py  run_goal()
        ├─ 取 goal = goals.json["look_main"]
        ├─ 展开 steps → 每个 step 变成一个 skill 调用
        └─ 对每一步：
             SafetyGate.check_can_act()   ← 7 道检查，任何一道不过就抛 SafetyError
             AgentClient.run_skill(skill, args, dry_run, deadline_ms)
        │
⑤ engine/protocol.py  POST http://<IP>:8765/v2/skill
        headers: X-Token（同时兼容 Authorization: Bearer）
        body:    {"skill":"assert_main","args":{},"dry_run":true,"deadline_ms":8000}
        │
⑥ 电脑侧 agent（另一台机器上跑的程序，不在本仓库）
        ├─ dry_run=true → 只截屏 + 模板匹配 + 规划，动作放进 would_do，不产生任何输入事件
        ├─ dry_run=false → 真正 tap / swipe / key
        └─ 返回 {"ok":true,"final_state":"main_map","would_do":[],"elapsed_ms":420}
                  或 {"ok":false,"error_class":"E_UI",...}
        │
⑦ 回到 planner：按 final_state 更新状态机；ok=false 时按 error_class 决定
        E_UI / E_TIMEOUT → 记一次失败（可能触发熔断）
        E_DEVICE / E_PAUSED / E_CALIB → 立即终止，不重试
        │
⑧ engine/trace.py  RunRecorder
        ├─ 逐步记录：skill、耗时、state、confidence、结果
        ├─ scrub() 脱敏（token/password/secret/key/cookie/session → 打码）
        └─ TraceStore.write() 落盘，并按限额裁剪旧文件
        │
⑨ plugin.py  _format_run() → 把 final_state、每步结果、耗时整理成一段人话回复
```

关键点：**插件从头到尾没有见过一个像素，也没有一个坐标。** 它只发"做什么"，agent 回"看到了什么、做了什么"。

## 五、六个关键设计，逐个拆开

### 5.1 三层抽象：状态 → 技能 → 目标

这是整个适配包的骨架，全部是 JSON，没有代码。

```
状态（states.json）   ：一个可以稳定识别的界面特征（模板图 + 置信度阈值）
技能（skills.json）   ：一组原子动作（assert / wait_for / tap / swipe / key）
目标（goals.json）    ：用户能说出口的一件事，由若干技能排列组合而成
```

以 `demo` 包的真实内容为例：

```jsonc
// states.json —— "loading" 的置信度阈值刻意压低，因为动画帧之间差异大
"loading": { "templates": ["templates/loading.png"], "min_confidence": 0.62 },
"main_map": { "templates": ["templates/main_map.png"], "min_confidence": 0.78 },
"unknown": { "templates": [] }        // 引擎的终止条件：此状态不允许执行任何操作

// skills.json —— demo 包里所有技能只有 assert / wait_for，没有 tap/swipe/key
"assert_main": {
  "pre_states": ["any"],
  "steps": [ { "op": "assert", "state": "main_map" } ],
  "expect_state": "main_map",
  "timeout_ms": 8000,
  "retryable": true
}

// goals.json —— 目标是技能的排列组合，不含任何坐标或识别细节
"look_main": {
  "requires_state": "any",
  "steps": [ { "skill": "assert_main" } ],
  "on_fail": "abort",
  "max_attempts": 1
}
```

这样分层的好处是三个角色各改各的：写文案的只碰 `goals.json`，调识别的只碰 `states.json` 和模板图，写动作的只碰 `skills.json`。

### 5.2 坐标绝不进仓库

这条靠代码强制，不靠自觉。`game_adapter/base.py` 里有两道检查：

- `_reject_coords(node, where)`：递归遍历适配包 JSON，任何形如 `x` / `y` / `coord` / `point` 的字段直接判包非法，报错指出具体路径。
- `validate_config_keys(config)`：配置里出现越界键（比如试图加一个坐标块）同样拒绝。

`tools/selftest.py` 里还有 `scan_coordinates()` 作为第三道，扫描整个包。三道下来，"有人在适配包里偷偷写坐标"这件事在提交前就会失败。

### 5.3 七道闸门

`engine/gate.py` 的 `check_can_act()` 顺序执行，任何一道不过就抛 `SafetyError`，动作不会发生：

| # | 闸门 | 默认值 | 作用 |
| --- | --- | --- | --- |
| 1 | 演练模式 | 开启 | 只识别不动作；请求可以更严，**不能更松** |
| 2 | 免责确认 | 未确认 | 未读免责不许实跑，确认状态持久化 |
| 3 | 暂停热键 | 空（=不可实跑） | 没配置热键就不允许实跑，必须有一个能物理停下的手段 |
| 4 | 校准状态 | 未校准 | agent 接口变化后必须重新校准，否则坐标不可信 |
| 5 | 动作限流 | 20 次/分钟 | `deque` 滑动窗口，防止脚本跑飞 |
| 6 | 熔断 | 连续失败 1 次 → 冷却 300 秒 | 失败即停，不硬撑 |
| 7 | 会话上限 | 1800 秒 | 超过自动结束，避免无人值守跑整夜 |

`installation_problems()` 负责把"为什么不能实跑"翻译成人话列出来，`/ship status` 直接显示这一段。设计意图是：用户看到的第一个东西应该是"还差什么"，而不是一个错误码。

### 5.4 错误分类驱动熔断

错误不是一律平等。`error_class` 决定后续动作：

| error_class | 含义 | 处理 |
| --- | --- | --- |
| `E_UI` | 界面不符 / 认不出 | 记一次失败，计入熔断 |
| `E_TIMEOUT` | 超时 | 记一次失败，计入熔断 |
| `E_DEVICE` | 设备断开 | 立即终止，不重试（重试一万次也没用） |
| `E_PAUSED` | 用户已暂停 | 立即终止，**不计失败**（用户主动叫停不算故障） |
| `E_CALIB` | 未校准 | 立即终止，提示去校准 |

把 `E_PAUSED` 摘出熔断统计是有意为之：否则用户点一次暂停就触发熔断冷却，界面会显示"因故障熔断"，误导排查方向。

### 5.5 轨迹与脱敏

每次运行都留一份轨迹（`traces/`，不进仓库）：

- 记录：目标名、是否演练、每步技能、耗时、观察到的 state 与 confidence、`would_do`、错误分类。
- 脱敏：`trace.py` 的 `_SECRET_KEYS = ("token", "password", "secret", "key", "cookie", "session")`，命中即打码，`scrub()` 递归处理嵌套结构。
- 限额：`_enforce_limits()` 按数量和体积裁剪，`cleanup()` 供手动清理。
- 诊断包：`build_diagnostics()` 打包成 zip，包含配置（已脱敏）、近期轨迹、可选截图（默认不含，且提示"分享前自行确认画面无敏感信息"）。

脱敏只按**键名**判断，不做"看起来像 token 的字符串"这种猜测。理由写在代码注释里：误伤比漏打更烦，脱敏一旦让正常信息消失，人就不信任它了。

### 5.6 协议协商

`capabilities` 里 `protocol` 字段是必须的。插件做**大版本**协商，不一致直接拒绝执行并说明两边版本。

协商发生在**第一次真正调用**时，而不是插件加载时。因为用户很可能先启动麦麦、再启动 agent；如果加载期就校验，顺序问题会表现为"插件坏了"。所以 `on_load` 永远成功，这是刻意的。

## 六、制作流程（实际走的九步）

下面的顺序就是真实开发顺序，每一步都给了产出物和验收标准。

### 阶段 0：定边界，写死三条铁律

- 产出：一句话架构（插件管"要不要做"，agent 管"看到什么、怎么动"）。
- 验收：能用一句话说清"为什么坐标不能进插件"。

### 阶段 1：配置与错误（`engine/config.py`、`engine/errors.py`）

- 配置拆六节：`plugin` / `connection` / `safety` / `adapter` / `notify` / `runtime`，每节一个 dataclass + `from_dict`。
- 错误分 7 个子类 + 1 个基类（基类 `ShipError`，子类 `EnvError` / `ProtocolError` / `UiError` / `StateError` / `TimeoutError_` / `SafetyError` / `ConfigError`），每个错误必须能给出 `hint`；`error_from_code()` 负责把 agent 返回的 `error_class` 映射回异常。
- 关键函数：`effective_dry_run()` —— 配置演练时，请求无论怎么传都是演练（只能加强不能削弱）。
- 验收：所有报错都能回答"我该怎么做"。

### 阶段 2：协议层与契约文档（`engine/protocol.py`、`docs/电脑侧Agent契约.md`）

- 先写契约文档，再写客户端代码。八个接口：`health` / `capabilities` / `observe` / `skill` / `pause` / `resume` / `calibrate` / `screenshot`。
- `AgentClient` 每个方法对应一个接口，统一 `_request()` 处理鉴权、超时、JSON 解析、错误映射。
- 验收：契约文档里的每个字段，代码里都能找到对应处理。

### 阶段 3：闸门（`engine/gate.py`）

- 先写闸门，再写编排。顺序反了会写出"能跑但没有刹车"的东西。
- 每个闸门都要能被单独测试（`set_calibration` / `set_pause_hotkey` / `record_failure` / `record_success` 都是可注入的）。
- 验收：单独调用 `check_can_act()` 能复现道七种拒绝。

### 阶段 4：适配层与 demo 包（`game_adapter/base.py`、`game_adapter/demo/`）

- `base.py` 解析四个文件，做禁坐标校验；`discover_packs()` 扫描目录，坏包不影响好包加载。
- demo 包必须**只读**：所有技能只有 `assert` / `wait_for`，没有任何 `tap` / `swipe` / `key`。这样即使有人打开实跑，demo 包也动不了任何东西。

## 七、真实踩过的坑（这部分最值钱）

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| 演练模式的**负向用例**（本该失败的）全部 "ok" | agent 的 `dry_run` 分支只记了 `op + target`，没解析坐标、没校验键名，于是 `F99` 这种非法坐标也判成功 | 演练分支必须同样解析坐标与键名，否则负向用例是假绿 |
| `calibration.ok=true`，但之后识别不稳 | `anchors=1`，契约要求 ≥3；单个锚点无法约束缩放 | 定标后检查锚点数量，不足视为未校准 |
| 重新校准总是失败 | 自测残留了旧尺寸（`1214x653`）没被刷新，模板按错误尺寸生成 | `POST /v2/calibrate` 强制重定标，并按当前画面重做模板 |
| 插件装上后行为不对 | `_manifest.json` 声明 Host 1.4.0–1.4.99 / SDK 2.22.0–2.22.99，实际是 Host 1.3.1 / SDK 2.8.2；靠"强制兼容"才加载成功 | 版本区间按实测放宽（Host ≥ 1.3.0、SDK ≥ 2.8.0），README 如实写实测版本 |
| 文本文件看起来全是乱码 | PowerShell 5.1 默认按 ANSI 读 UTF-8 文件 | 文件本身没问题（全部 UTF-8），换 `read_text` / 显式 `-Encoding utf8` 读 |
| `git push` 报 `Recv failure: Connection was reset` | `github.com:443` 直连被阻断（`Test-NetConnection` 失败、无系统代理），而 `api.github.com` 可通 | 改用 Git Data API 上传：`blobs → trees → commits → 更新 ref → 打 tag` |
| 微软商店里"插件坏了"这类投诉 | 加载期做协议校验，用户先启动麦麦后启动 agent 就报错 | 加载永远成功，协商推迟到第一次真实调用 |

这些坑有一个共同点：**都是"看起来成功了但实际没验证"**。演练判成功、校准判 ok、加载判成功、推送判成功 —— 每一个假绿都要靠"再走一步真链路"才能暴露。

## 九、如果要复刻（换个游戏 / 换个项目）

最小路径，按依赖顺序：

1. **先跑通自检**：`python tools/selftest.py` —— 不动任何业务代码，确认环境能跑。
2. **写 agent**：照 `docs/电脑侧Agent契约.md` 实现 8 个接口，先只实现 `health` / `capabilities` / `observe`（这三个是只读的），用 `/ship observe` 验证能连上、能返回 `state`。
3. **做校准**：这一步决定后面所有动作的可靠性。至少要 3 个锚点。
4. **写 demo 级适配包**：先只有 `assert` 技能的只读包（照抄 `game_adapter/demo/` 的结构），跑通"截图 → 识别 → 状态"这条链。
5. **加动作技能**：一个一个加，每加一个都在演练模式下验证 `would_do`，再单次真实执行，确认能停。
6. **升级闸门参数**：熟悉之后再调 `max_actions_per_min` / `breaker_threshold` / `session_max_sec`，默认值不要一开始就放宽。
7. **出包**：`python tools/pack_release.py`，先看它拦了什么，再决定要不要改白名单。

不要跳步。跳过第 2、3 步直接写动作技能，结果一定是"能跑但不可信"。
