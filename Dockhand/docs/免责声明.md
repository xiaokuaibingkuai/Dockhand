# 使用前须知（免责声明 v1）

> 这份文档的正文与 `engine/runtime.py` 里的 `DISCLAIMER` 常量**逐字一致**。
> 代码里那份是唯一权威，因为它会在你第一次尝试实跑时被原样打印出来。
> 改字必须两边一起改，并且把 `disclaimer_version` 加一。

---

## 一、原文

```
使用前确认：
1) 本插件通过模拟点击/按键操作游戏，属于非官方自动化方式，存在账号被处罚的风险；
2) 建议只在小号上验证，出问题不影响主号；
3) 默认以演练模式运行，只有你明确关闭 dry_run 才会真正操作；
4) 你必须自行确认该游戏的服务条款是否允许此类操作；
5) 作者不对因使用本插件导致的任何账号、数据或财产损失负责。
确认无误后，把配置里的 safety.disclaimer_accepted 改为 true。
```

聊天里发 `/ship disclaimer` 看到的就是这段。

---

## 二、三条确认途径

| 途径 | 操作 | 适用 |
| --- | --- | --- |
| 配置文件 | 把 `safety.disclaimer_accepted` 改成 `true` | 手改 config.toml 的人 |
| WebUI | 在插件配置页勾选同名开关 | 用面板的人 |
| 聊天命令 | 发 `/ship accept` | 手机上操作的人 |

`/ship accept` 会在插件数据目录写一个 `disclaimer_accepted.json`，记录确认时间与声明版本。重启后仍然有效——不需要每次启动重新确认。

配置与本地标记是"或"的关系，任一为真即视为已确认。`/ship status` 里的 `source` 字段会显示是哪一种（`config` / `local` / `none`），用于回答"我明明勾了为什么还说没确认"这类问题。

**注意**：第 5 条末尾那句"把配置改成 true"是原文的一部分，我没有改它。但你用 `/ship accept` 也算数，不必非去翻配置文件。改动原文会让"用户看到的"和"用户同意的"对不上，这种事不该为了措辞顺手而做。

---

## 三、确认前后，行为差在哪

| 项目 | 未确认 | 已确认 |
| --- | --- | --- |
| 只读看界面（`ship_state`） | 可以 | 可以 |
| 演练执行（`dry_run=true`） | 可以 | 可以 |
| 实跑（`dry_run=false`） | **拒绝**，并在提示里贴出全文 | 允许（仍需过校准与热键检查） |
| 出诊断包 | 可以 | 可以 |

也就是说：**不确认也能把整套东西试一遍**，只是不会真的动你的游戏。这是刻意的——让人在没有任何风险的情况下看清它做什么，比逼人先点"我同意"更有可能被真的读完。

---

## 四、风险说具体一点

"存在账号被处罚的风险"这句话太笼统，容易变成谁都不看的模板文字。具体是什么风险：

1. **账号处罚**。模拟点击与人类操作在系统层面有差异（时序规律、触摸面积、输入设备标识等）。游戏厂商是否检测、检测到什么程度，不在本插件的控制范围内，也无法通过本插件确认。这是本插件**不承诺**的事情。
2. **误操作导致的游戏内损失**。识别错一次就可能点错一个按钮。可能的结果包括：误消耗资源、误升级、误购买。演练模式与熔断机制是为了压这个风险，但不是零风险。
3. **违反服务条款**。多数游戏的用户协议禁止使用第三方自动化工具。是否执行这条、执行到什么程度，由厂商决定。**这需要你自己去看你玩的游戏的服务条款**——本插件不能替你判断，也不会替你判断。
4. **多开与代练场景风险更高**。同一设备或同一网络下的多账号自动化，通常比单账号更容易被关联。

### 本插件不做什么

为了不被误解成"安全方案"，明确列出它**不会**做的事：

- **不做反检测**。不伪装输入时序、不随机化触摸特征、不规避任何检测机制。它就是一个老老实实的自动化工具。
- **不承诺不封号**。任何声称"绝对安全"的自动化工具都在骗人。
- **不隐藏自己的行为**。所有执行都留轨迹（`traces/`），`/ship status` 里能看到当前模式，日志里能看到每一步。
- **不上传任何数据**。插件不联网到作者服务器；诊断包是你自己生成、自己决定发给谁的本地文件。

### 它做了什么来降低风险

| 机制 | 作用 |
| --- | --- |
| 默认 `dry_run=true` | 装完不会自己动起来 |
| 三道演练保证 | 配置、闸门、agent 三层都拦住真实输入 |
| 认不出就停 | `unknown` 是终止条件，不是"猜一个继续" |
| 熔断 | 连续失败自动停，不会反复试 |
| 限流 | 每分钟动作数上限，避免高频操作特征 |
| 会话时长上限 | 单次执行有时间上限，防止挂机跑一整晚 |
| 暂停热键 | 出问题时能物理按停（局限见下） |

## 五、关于热键，一句必须说清的话

`safety.pause_hotkey` 填了之后，`/ship status` 会显示 `F12（未验证）`。

"未验证"不是偷懒：插件只能检查你**填没填**，无法确认这个热键在电脑侧 agent 上真的注册成功、真的按下去能停。这个验证只能你来做——装完之后跑一个无害的只读目标，按一下热键，然后确认 `paused` 变成 true、后续执行被拒绝、`/ship resume` 能恢复。

**"以为有急停、实际按下去没反应"是最坏的情况。** 所以这里宁可显示"未验证"，也不显示"已配置"。

---

## 六、确认之后还能反悔吗

可以。把 `disclaimer_accepted` 改回 `false`，或删掉数据目录里的 `disclaimer_accepted.json`，插件立刻回到"只能演练"的状态。**当前正在执行的目标不会因此中断**——要中断请用暂停（热键或 `/ship pause`）。

撤销这一点是设计过的：如果撤销要重启插件才生效，人在着急的时候就不会去撤销了。

---

## 七、声明版本

当前 `disclaimer_version = 1`。

改动声明的实质内容时（不是修错别字）必须加版本号，并让已确认的用户重新确认。判断标准很简单：**如果新加的这一句会让某个人改变"要不要用"的决定，那就是实质改动。**
