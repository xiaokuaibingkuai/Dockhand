# 电脑侧 agent 契约（v2）

插件只负责"要不要做、做什么"，agent 负责"看到了什么、怎么动"。

这份文档是给**写 agent 的人**看的（很可能就是你自己）。它规定两端之间的 HTTP 接口，以及三条必须由 agent 侧保证的行为：演练不落地、认不出就停、热键真的能停。

> 为什么 agent 必须在电脑上：插件跑在 MaiBot 的 Runner 里，那是个容器，看不到你的屏幕，也没有 adb。识别需要的分辨率、缩放、DPI、语言，只有那台接着手机/模拟器的机器自己知道。把这些搬到插件里，等于把"只在我这台机器上能用"写进代码。

## 一、连接与鉴权

```
http://<电脑局域网 IP>:8765
```

- 所有请求带 `X-Token: <token>`（令牌在 agent 侧生成）。插件发的是这个头。
- **同时请接受 `Authorization: Bearer <token>`**：别的人可能用脚本或别的客户端直接调这个接口，两种写法都认能省掉一整类"401 但 token 明明一样"的问题。
- 令牌比对用常量时间比较（`hmac.compare_digest`），不是洁癖：普通 `==` 会在第一个不同的字节返回，理论上可被逐字节试探。
- 只监听局域网，**不要映射到公网**。这个接口能截图、能模拟点击，暴露在公网上等于把设备交出去。
- 令牌为空时，agent 应当**拒绝**所有请求并提示"未设置令牌"。默认拒绝比默认放行安全，这里不提供"方便模式"。

插件侧的 `base_url` 填 `127.0.0.1` 是最常见的错误：MaiBot 在容器里，`127.0.0.1` 指向容器自己。文档、错误提示、`/ship status` 三处都重复了这一点，因为它是新用户遇到的第一个问题。

## 二、接口清单

| 方法 | 路径 | 用途 | 幂等 |
| --- | --- | --- | --- |
| GET | `/v2/health` | 存活检查 | 是 |
| GET | `/v2/capabilities` | 能力与版本协商 | 是 |
| GET | `/v2/observe` | 只读看当前界面 | 是 |
| POST | `/v2/skill` | 执行一个技能 | 否 |
| POST | `/v2/pause` | 暂停 | 是 |
| POST | `/v2/resume` | 恢复 | 是 |
| POST | `/v2/calibrate` | 校准 | 否 |
| POST | `/v2/screenshot` | 截图存档 | 否 |

### GET /v2/health

```json
{"ok": true, "agent_version": "1.0.0", "device": "emulator-5554", "uptime_sec": 812}
```

### GET /v2/capabilities

```json
{
  "protocol": 2,
  "agent_version": "1.0.0",
  "resolution": [1280, 720],
  "paused": false,
  "calibration": {"ok": true, "reason": ""},
  "skills": ["assert_main", "assert_fleet", "wait_loading"],
  "features": ["dry_run", "would_do", "diagnostics"]
}
```

- `protocol` 必须返回。插件做**大版本**协商，不一致直接拒用并说明两边版本。
- 协商发生在**第一次真正调用**时，不在插件加载时。因为用户很可能先启动麦麦再启动 agent；加载失败会让顺序问题变成"插件坏了"。加载永远成功，是刻意的。
- `resolution` 是 agent 实际看到的画面尺寸（不是设备标称分辨率）。投屏缩放、模拟器缩放都会改变它。
- `paused` 必须是**实时值**。插件用它显示状态，不是缓存值。
- `calibration.ok` 为 false 时，`reason` 要写人话（"分辨率从 1280x720 变成 1920x1080，需要重新校准"），不要写错误码。

### GET /v2/observe

```json
{
  "state": "main_map",
  "confidence": 0.93,
  "resolution": [1280, 720],
  "ui_hash": "a1b2c3",
  "elements": {"fleet_btn": {"x": 120, "y": 900, "score": 0.93}}
}
```

- `state` **必须返回**，认不出就返回 `"unknown"`，`confidence` 给真实值（可以是 0）。
- **不许猜。** 认不出时返回最像的那个界面，是这套系统里最危险的一个"善意"——它会让调用方以为识别成功了，然后继续在错误的界面上执行动作。
- `elements` 里的 `x/y` 是**运行时结果**，每次现算。它不进适配包、不进配置、不落盘。这是"坐标只存在于现场"的具体含义。
- `ui_hash` 可选，用于判断"是不是同一个界面"（同 hash 说明没变化，可以省一次识别）。

### POST /v2/skill

请求：

```json
{"skill": "assert_main", "args": {}, "dry_run": true, "deadline_ms": 60000}
```

响应：

```json
{"ok": true, "final_state": "main_map", "would_do": [], "elapsed_ms": 420}
```

- `dry_run: true` 时，agent **必须**只做识别与计划，不产生任何输入事件。原本要做的动作放进 `would_do`：

```json
{"ok": true, "final_state": "main_map", "would_do": [{"op": "tap", "target": "fleet_btn"}]}
```

- `final_state` 是执行结束后 agent 观察到的界面。插件用它更新状态机。
- `ok: false` 时必须带 `error_class`，插件用它做熔断分类：

| error_class | 含义 | 插件反应 |
| --- | --- | --- |
| `E_UI` | 界面不符或认不出 | 记一次失败，可能熔断 |
| `E_TIMEOUT` | 超时 | 同上 |
| `E_DEVICE` | 设备断开 | 直接终止，不重试 |
| `E_PAUSED` | 已暂停 | 直接终止，不计失败 |
| `E_CALIB` | 未校准 | 直接终止，提示去校准 |

分类的意义在于熔断策略：`E_PAUSED` 不是失败，不能计入熔断；`E_DEVICE` 重试一万次也没用，不如立刻停。

- 这个接口**不重试**。为什么：`POST /v2/skill` 不是幂等的。一个"确认领取"的技能重试一次，就是领两次。重试逻辑放在插件侧（明确知道哪些技能 `retryable: false`），而不是在网络层偷偷重试。

### POST /v2/pause

```json
{"reason": "remote"}
```

agent 收到后必须按顺序做三件事：

1. **立即释放所有按住的触点/按键**（先抬手，再干别的；否则会留下一个按住不放的手指）
2. 设置 `paused = true`（`/v2/capabilities` 要能立刻反映）
3. 拒绝后续所有 `/v2/skill`，返回 `E_PAUSED`

暂停是比熔断更强的保护，优先级最高。恢复只能通过 `/v2/resume` 或本地热键。

### POST /v2/calibrate

```json
{"ok": true, "resolution": [1280, 720], "scale": 1.0, "anchors": 4, "notes": ""}
```

校准必须**在 agent 侧完成**（它才能截屏）。细节见下面第四节。

### POST /v2/screenshot

```json
{"ok": true, "path": "shots/2026-11-14_1930.png"}
```

用于用户在 `/ship diag` 时附带现场画面。agent 应当：

- 只保留最近 N 张（建议 10），自动清理
- 默认不随诊断包外发（见第五节）

## 三、演练语义：`dry_run` 的三重保证

演练模式是这套系统能让人放心试用的前提。它在三层同时生效，任何一层单独存在都不够：

| 层 | 做法 | 防的是什么 |
| --- | --- | --- |
| 插件配置 | `safety.dry_run = true` 时，`run_goal` 强制把所有调用改成 dry_run | 用户忘了自己开了实跑 |
| 闸门 | `gate.check_can_act()` 在演练时不消耗限流配额，但仍执行暂停/熔断检查 | 演练状态下也被暂停/熔断拦住 |
| agent | 收到 `dry_run: true` 后只在内存里计划，`would_do` 返回计划 | 插件算错了，也不会真的点下去 |

第三层是最关键的：它是唯一能保证"即使上面两层都错了，也没点下去"的一层。所以 agent 的实现里，`dry_run` 的判断必须放在**产生输入事件的那一行之前**，而不是在函数入口处设置一个变量然后忘了判。

## 四、校准向导规范

校准解决的问题：agent 需要知道"我这块屏幕上的一个像素，对应游戏里的什么相对位置"。

### 必须做的三步

1. **分辨率与缩放探测**
   - 截一张图，报告实际像素尺寸
   - 报告系统缩放比例（模拟器/投屏软件常有自己的缩放）
   - 如果与上次记录不一致 → `calibration.ok = false`，`reason` 写明"从 A 变成 B"

2. **锚点确认（至少 3 个，建议 4 个）**
   - 让用户手动点几个**稳定不变的界面元素**（例如屏幕四角的安全区域、主界面独有的按钮）
   - agent 记录这些元素通过模板匹配得到的相对位置（归一化到 0~1）
   - 一致性校验：同一个元素连续匹配 3 次，位置偏差超过阈值（建议 2%）就判定校准失败

3. **匹配自检**
   - 用校准结果反过来识别 `entry_states`
   - **认不出任何一个 entry_state 就不算校准成功**——这是硬门槛：认不出关键界面却允许启用，等于让它在一个自己看不懂的界面上开始点

### 失败时怎么说

| 情况 | 提示文本（写给人看） |
| --- | --- |
| 分辨率变化 | "画面尺寸从 1280x720 变成 1920x1080，需要重新校准（模拟器缩放或投屏设置改过？）" |
| 锚点不稳定 | "第 2 个锚点三次匹配位置差异 5.2%，超过 2% 上限。可能是因为那个位置有动画，换一个不动的元素" |
| 认不出入口界面 | "校准通过了，但认不出主界面模板。可能是：模板图不匹配这个分辨率、游戏 UI 缩放不是默认值、或者当前不在主界面" |

提示要写"最可能的三个原因 + 怎么改"，不要只写"校准失败"。

### 什么时候必须重新校准

- 分辨率或缩放变化（agent 自己检测，主动把 `calibration.ok` 置 false）
- 换了模拟器/投屏软件
- 游戏更新改了 UI
- 用户在 `/ship status` 里看到 `未校准`

插件侧的处理：`require_calibration = true`（默认）时，未校准直接拒绝实跑，**但允许演练**。因为演练正是用来确认"校准到底对不对"的。

## 五、诊断包与脱敏

`/ship diag` 生成一个 zip，用户把它发出来就能定位问题。内容清单：

| 文件 | 内容 | 脱敏 |
| --- | --- | --- |
| `summary.txt` | 时间、插件版本、agent 版本、协议版本、模式 | — |
| `config.json` | 当前配置快照 | **令牌替换为 `<redacted>`；base_url 只保留主机名首段** |
| `gate.json` | 闸门快照（限流窗口、熔断状态、暂停原因） | — |
| `agent.json` | `/v2/capabilities` 全量返回 | 设备序列号打码 |
| `trace.jsonl` | 最近 N 条执行轨迹（目标、每步结果、失败分类） | 不含聊天内容 |
| `screenshots/` | 现场截图（**仅当用户显式要求时包含**） | 默认不含 |

### 脱敏规则（agent 和插件都要遵守）

必须抹掉：

- 令牌、Cookie、任何 `Authorization` 头
- 设备序列号、IMEI、账号名、区服 ID
- 聊天内容、用户昵称、消息 ID
- 截图里的聊天窗口、好友列表、广告位（如果截图必须包含，先打码）

可以保留：

- 分辨率、缩放比例、界面状态名、置信度
- 错误分类与文本（它们是排查的核心）
- 技能名与步骤序列（不含坐标即可）

`/ship diag` 的返回里有一句提示："如果包含截图，请自行确认画面里没有敏感信息再分享"。这不是免责套话——截图是最容易带出隐私的一项，而用户通常不会想到。

## 六、暂停热键：能力与局限必须分开说

### agent 侧要求

- 注册**全局**热键（默认建议 F12），在任何窗口焦点下都生效
- 按下后：立即释放所有按住的触点 → `paused = true` → 拒绝后续 skill → 记录一条日志
- 热键未配置时，`capabilities.features` 不要声称支持暂停；插件会据此提示用户

### 插件侧能做什么、不能做什么

**能**：检查 `safety.pause_hotkey` 是否填写；检查 agent 的 `features` 是否包含暂停能力；在状态里显示"热键：F12（未验证）"。

**不能**：验证这个热键在 agent 上真的注册成功、真的能按停。

这个局限必须明确写出来，而不是假装校验通过。因为"以为有急停，实际按下去没反应"是最坏的情况——用户会因为信任它而在出事时多等几秒。

所以 `/ship status` 里的措辞是 `热键：F12（未验证）`，README 里也重复了一遍。诚实地说明一个保护措施的边界，比让它看起来完整更重要。

### 部署后请真的按一次

装完之后，让它跑一个无害的只读目标，然后按热键，确认：

1. `paused` 变成 true（`/ship status` 能看到）
2. 后续执行被拒绝
3. `/ship resume` 能恢复

这三步验过一次，这个保护才算存在。

## 七、最小实现建议

如果从零写一个 agent，顺序建议这样：

1. **先只有 `/v2/health` + `/v2/capabilities`**，把协议协商跑通。
2. **加 `/v2/observe`**，先不做识别，固定返回 `"unknown"`。跑一次 `/ship observe`，确认链路通。
3. **加模板匹配**（OpenCV `matchTemplate` 就够，多尺度匹配应对缩放）。先把 demo 包的四个界面认出来。
4. **加 `/v2/skill` 的 dry_run 分支**，只返回 `would_do`，不落地。这一步跑通，演练模式就完整了。
5. **最后**才加真实的 tap/swipe 实现，并且在此之前把热键做完。

顺序很重要：先让"什么都不做"这条路完全通，再让"能做点什么"接上去。反过来做，第一次测试就会真的点屏幕。

技术栈建议：

- 截图：`adb exec-out screencap -p`（真机）或模拟器自带接口
- 匹配：OpenCV `matchTemplate`，多尺度 + 灰度 + 边缘特征
- 输入：`adb shell input tap`（简单可靠）或 `minitouch`（更快）
- 服务：FastAPI / Flask 均可，关键是**同步执行**——`/v2/skill` 是阻塞的，返回时技能已经跑完

## 八、改动这份契约时

- `protocol` 大版本不变时，只能**加**字段，不能改已有字段的语义
- 加字段：插件忽略不认识的字段，agent 也可以忽略
- 改语义：必须升 `protocol`
- 插件在 `capabilities()` 里做严格相等判断（`remote != PROTOCOL_VERSION` 就拒），所以升版本必须两边一起升。这是刻意的：这个系统的失配成本比"多支持一个旧版本"高得多。
